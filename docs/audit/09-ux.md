# Phase 11 — UI/UX Review

**Verdict: 6/10** — the highest score in this audit. The design foundations are genuinely good. Three
things hold it back: **the app shell is desktop-only at every viewport**, accessibility is thin enough to
fail procurement, and fabricated data undermines the credibility of screens that are otherwise well built.

---

## What is genuinely good

**Empty, loading, and error states are handled better than in most shipped enterprise software.**

- 17 `loading.tsx` files, all using a shared shimmer (`src/components/AppSkeleton.tsx`).
- 17 matching `error.tsx` files with a shared `AppErrorState` including `reset()`.
- A reusable `EmptyState` component (icon + title + description + CTA) used across nine pages, plus
  purpose-built empties — `EmptyChart` in `ReportsView.tsx:50`, "No Zombie Licenses Found", the CMDB
  empty state.

Most teams ship the happy path and retrofit these. Having them systematised from the start is a real
quality signal.

**The design system is small, coherent, and correctly scoped.** Eight primitives in `src/components/ui/`
— `Button`, `Panel`, `Badge`, `StatTile`, `PageHeader`, `Field`, `Table`, plus `cn`/`focusRing`. Variants
are semantic (`statusTone`, `priorityTone`) rather than visual, which is the right abstraction for a
status-heavy product.

**The design language is well chosen.** "Enterprise calm, not sci-fi spectacle" (per `AGENTS.md`) is
exactly right for an operations console people stare at for eight hours. Signal-mint accent with semantic
rose/amber/emerald for SLA status is disciplined, and Bricolage Grotesque restricted to page titles keeps
the chrome quiet.

**AI deflection before ticket creation** (`DeflectionPanel.tsx`) is genuinely modern UX — answer first,
form only if unresolved.

## Problem 1 — the application is unusable on mobile and tablet

`src/components/AppShell.tsx:26`:

```tsx
<main className="fixed top-[88px] left-72 right-8 bottom-8">
```

**No breakpoint prefix.** The 288px sidebar offset applies at every viewport width. `Sidebar.tsx:75` is
`fixed left-0 w-64` with no mobile drawer and no hamburger. On a phone, content is pushed almost entirely
off-screen.

The breakpoint counts confirm it: `/assets`, `/catalog`, `/cmdb`, `/analytics`, `/my-requests`,
`/approvals`, `/knowledge`, `/search`, `/reports`, and **every `/admin/*` page contain zero responsive
classes.** The marketing pages have 50; the DEX dashboard has 12.

**Why this matters commercially:** the employee portal is the surface most people touch, and employees
raise tickets from phones — that is when they are away from the broken laptop. An IT platform whose
self-service portal does not work on a phone will fail user-acceptance testing at most enterprises. It is
also an accessibility issue: no responsive layout means no reflow, which is a WCAG 2.1 AA failure
(1.4.10 Reflow).

**Fix, in order:**
1. Make the shell responsive: sidebar collapses to an overlay drawer below `lg`, `main` drops its offset.
2. Employee-facing pages first — portal, incidents, catalog, knowledge, my-requests.
3. Wide tables get a card layout below `md` rather than horizontal scroll.
4. Agent/admin consoles can stay desktop-first; that is a defensible product decision. The employee
   portal cannot.

*Effort: Medium. This is the highest-priority UX work.*

## Problem 2 — accessibility will fail a procurement review

**40 `aria-*` attributes across the entire codebase. Two `role` attributes. Zero `sr-only` utilities.**

| Issue | Location | Impact |
|---|---|---|
| Modals have no dialog semantics | `dex/page.tsx:831-1037` — hand-rolled `fixed inset-0` divs | No `role="dialog"`, no `aria-modal`, **no focus trap, no Escape handler**. Screen-reader users cannot perceive them; keyboard users get lost behind them |
| Toggles are plain buttons | DEX auto-pilot, smart contracts | No `role="switch"`, no `aria-checked` — state is invisible to assistive tech |
| Tooltips are hover-only CSS | `dex/page.tsx:552` | Unreachable by keyboard and touch |
| CMDB tree nodes are clickable `<div>`s | `CmdbView.tsx:57-58` | No `tabIndex`, no key handler, no `role="treeitem"` — completely keyboard-inaccessible |
| Charts have no text alternative | All Recharts except `DashboardChart` | Data is invisible to screen readers |
| No skip link, no landmarks | Global | Keyboard users traverse the full nav on every page |
| No `not-found.tsx`, no `global-error.tsx` | `src/app` | `notFound()` at `incidents/[id]/page.tsx:39` falls through to the Next.js default |

**Government and public-sector buyers require a VPAT or an EN 301 549 conformance statement.** US federal
buyers require Section 508. You cannot produce a credible VPAT from the current state — and you named
government as a target market.

**Positives worth keeping:** a `focusRing` token applied consistently across primitives,
`aria-current="page"` on active nav, `aria-label` on icon-only buttons, and a global
`prefers-reduced-motion` block in `globals.css:117`.

**Fix:** adopt Radix UI (or React Aria) for Dialog, Tabs, Tooltip, Switch, and Dropdown — the primitives
you are hand-rolling are precisely the ones with the hardest accessibility requirements, and Radix solves
focus management, ARIA, and keyboard interaction correctly for free. Add `axe-core` to CI. Target WCAG
2.1 AA and publish a VPAT.

*Effort: Medium (Radix migration is mostly mechanical). Impact: unblocks public sector.*

## Problem 3 — fabricated data on production screens

Detailed in [Phase 4](04-dex.md); summarised here because it is fundamentally a UX-credibility failure:

The DEX dashboard's **largest chart** ("Global Network Latency") is 7 hardcoded points sitting directly
beneath a `Badge tone="success">Live agent data`. The "Fleet Health" chart shows 850/120/30 while the
real device count sits in a tile a few hundred pixels above. "Auto-Remediations Today" is a `useState(0)`
that resets on reload. The remediation history log shows identical fixed timestamps to every user.

`seedDemoData()` (`dexActions.ts:55-101`) writes fabricated crashes, software usage, and a **security
posture** into any tenant with empty tables, on every dashboard load.

The Flow Designer always renders a hardcoded "Hardware Provisioning Flow" title with an `Active` badge
regardless of what is loaded. The walk-up kiosk greets everyone as "Hi, Priya Sharma!"

Two ROI calculators exist, differing only in filename case (`RoiCalculator.tsx` and
`roi-calculator.tsx`), producing **different numbers on different pages of the same website**.

**Every one of these has real data available behind it.** `latencyMs` is in `DeviceMetric`; command
counts are in `RemoteCommand`. This is a day of work that converts your most impressive screen from
"demo" to "product."

## Missing primitives

`src/components/ui/` lacks **Modal/Dialog, Tabs, Tooltip, Dropdown, Pagination, Avatar, Skeleton,
Checkbox, Radio, Switch** — so each is hand-rolled per use site, inconsistently and inaccessibly. Adding
them (via Radix) is the single highest-leverage design-system investment.

Also note `cn.ts` is a dependency-free class joiner with **no `tailwind-merge`** — conflicting utility
classes will not resolve correctly, producing subtle style bugs as the codebase grows.

---

## The theming architecture is fragile

Not Tailwind's `dark:` variant. Pages are authored in *dark* utility classes (`text-white`,
`bg-white/[0.02]`) and `globals.css:122-330` contains ~200 lines of hand-maintained overrides that flip
those classes for light mode (`.app-root.theme-dark .text-blue-400 → #38E8B0`).

**Any new page using an unmapped utility renders wrong in one theme, silently.** This scales badly and
the failure mode is invisible in review. `src/app/layout.tsx:66` separately applies `dark:` classes that
the theme system does not drive — two competing mechanisms.

*Fix:* migrate to semantic CSS variables (`--surface`, `--text-primary`, `--border`) set per theme, and
author components against tokens rather than raw colour utilities. Medium effort, and it removes an
entire class of recurring bug.

**Agent workspace** — the biggest service-desk efficiency win is a three-pane layout (queue │ ticket │
context) with keyboard-first navigation (`j`/`k` to move, `a` to assign, `r` to resolve, `/` to search)
and a context pane showing the caller's device health, open tickets, and AI-suggested resolutions.
Agents live in this screen for eight hours; keystroke efficiency is the metric that matters, and it is
what separates tools agents like from tools they tolerate.
